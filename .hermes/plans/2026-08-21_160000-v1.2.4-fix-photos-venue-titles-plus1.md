# v1.2.4 Fix Plan — Photos, Venue Preview, TitleA/B Removal, Plus1 Editor

**Goal:** Fix 4 issues in one atomic push.

## Task 1: Photos persistent storage

**Root cause:** `PHOTO_STORAGE_DIR` defaults to `<cwd>/storage/photos/`. Docker rebuild destroys it. The fix: add a persistent Docker volume AND make the photo endpoint more resilient.

**Files:**
- Modify: `docker-compose.yml` (add volume for photo storage)
- Modify: `.env.example` (document PHOTO_STORAGE_DIR)
- The endpoint already accepts guest access AND panel session — no code change needed

**Verification:** Upload a photo in panel → redeploy container → photo still visible.

---

## Task 2: Venue in previews

**Root cause:** Removed `venue` from `InvitationContent` but the preview in `InvitationDetail` still references `content.venue` which is now always empty.

**Fix:** The preview should pass the Wedding venue down from the InvitationsManager page. Add `venue` as a prop or fetch it from the profile endpoint in the component.

**Files:**
- Modify: `src/app/(panel)/invitaciones/page.tsx` — fetch wedding venue alongside invitations
- Modify: `src/components/invitations/InvitationsManager.tsx` — pass `venue` as prop to InvitationDetail
- Modify: `src/components/invitations/InvitationDetail.tsx` — accept `venue` prop, show in preview

---

## Task 3: Remove titleA/titleB from per-invitation editor

**Root cause:** The fields `invman.titleA` / `invman.titleB` in the detail editor let the couple override the bride/groom names per-invitation. These now come from Wedding (Profile) and don't belong here.

**Files:**
- Modify: `src/components/invitations/InvitationDetail.tsx` — remove the titleA/titleB inputs and from preview
- Modify: `src/lib/i18n.ts` — remove invman.titleA/titleB keys (or keep for compat)

---

## Task 4: Plus1 name editor per guest in invitation

**Requirement:** For each guest in an invitaton who has `plusOneAlloed=true`, show a text field to set/change `plusOneName`.

**This is tricky:** `InvitationDetail` recieves `invitation: InvitationDetailBase` which has `id, title, content?`. But to edit `plusOneName` we need the guests list. The `ManagerInvitation` type already has `guests: Array<{id:string,fullName:string,phone:string}>}`but not `plusOneAllowed`/`plusOneName`.

**Fix:** Add those fields to the type, pass them from the server, show inline editing in the invitation detail.

**Files:**
- Modify: `src/components/invitations/InvitationsManager.tsx` — ManagerInvitation type gets plusOneAllowed/plusOneName per guest
- Modify: `src/app/(panel)/invitaciones/page.tsx` — select plusOneAlloed/plusOneName from DB
- Modify: `src/components/invitations/InvitationDetail.tsx` — show +1 fields, save via PATCH /api/guests/:id
